# Plan 01-06: Admin product form — create + edit (4 tabs, image upload)

<goal>
Build the shared product form used by both create and edit: a 4-tab
layout (Basics, Images, Sizes, Variants) built on shadcn `Tabs`, with
`react-hook-form` + `zod` for the form layer, a drag-and-drop image
dropzone on the Images tab that POSTs to `/api/admin/upload` (the
Plan 01-04 route) and binds the returned path into `images[]`, and
repeatable rows for `images[]`, `sizes[]`, and `variants[]` via
`useFieldArray` (per D-17, not free-text comma lists). The form's two
server-component pages — `/admin/products/new` and
`/admin/products/[id]` — instantiate the shared component with
`initial` undefined or pre-fetched. After this plan, an admin can
create a product, edit it, and see the change reflected on the
storefront immediately (the storefront migration that makes the
reflection visible is Plan 01-07; this plan only wires the write path).

</goal>

<context>
Per `01-CONTEXT.md` D-16 (form covers all `Product` fields including
`id`, `name`, `price`, `image`, `category`, `group`, `section`,
`description`, `images[]`, `sizes[]`, `variants[]`; `id` is slug-typed
and validated client+server), D-17 (repeatable rows for `images[]`,
`sizes[]`, `variants[]`; `variants[]` is `{ colorName, colorValue,
image }`), D-18 (drag-and-drop or click-to-pick → `POST /api/admin/upload` →
saved under `/public/images/products/{timestamp}-{slug}.{ext}` → returns
public path), and D-20 (shadcn primitives + `cn()`). The visual and
copy contract is in `01-UI-SPEC.md` §Create / Edit form.

The schema the form must mirror is the Mongoose `ProductDocument` in
`backend/src/models/product.ts:13-25` (the frontend's `Product` type
in `lib/products.ts:13-25` is the same shape but the form posts to the
Next.js proxy which posts to the backend; the zod schema is the single
client-side validator and the backend re-validates with its existing
`validateProductPayload` at `backend/src/routers/clothes.ts:39-49`).

`useFieldArray` (from `react-hook-form`) is the right primitive for
repeatable rows; the form does NOT use comma-separated text inputs.
The upload route at `app/api/admin/upload/route.ts` (created in Plan
01-04) is the file destination; the form posts to it via `fetch` with
`FormData`. The toast from Plan 01-05 (`useAdminToast`) is reused for
save success / error feedback.

`/admin/products/new` is reachable by all admins; the
`/admin/products/[id]` page must pre-populate from the backend via
`backendFetch('/shop/products/' + id)` (server component) and pass the
hydrated product to the form.

</context>

<task id="01-06-03">
<action>Create the shared product form at
`components/admin/product-form.tsx` as a `'use client'` component,
plus the two server-component page entry points. The form's prop
signature is `{ initial?: Product; mode: 'create' | 'edit' }`. The
form uses `useForm` from `react-hook-form` with `zodResolver` from
`@hookform/resolvers/zod` and a zod schema that mirrors the backend
`ProductDocument` at `backend/src/models/product.ts:13-25` (and the
backend's `productPayload` at `backend/src/routers/clothes.ts:23-37`):
`z.object({ id: z.string().min(2, 'Slug must be at least 2 characters.').regex(/^[a-z0-9-]+$/, 'Use lowercase letters, digits, and dashes.'), name: z.string().min(1, 'Name is required.'), price: z.coerce.number().min(0, 'Price must be 0 or more.'), image: z.string().min(1, 'Primary image is required.'), category: z.enum(['clothing', 'shoe']), group: z.enum(['clothing', 'outerwear', 'shoes']), section: z.enum(['men', 'women', 'kids']), description: z.string().min(1, 'Description is required.'), images: z.array(z.string().min(1)).default([]), sizes: z.array(z.string().min(1)).default([]), variants: z.array(z.object({ colorName: z.string().min(1, 'Color name is required.'), colorValue: z.string().min(1, 'Color value is required (use an oklch string).'), image: z.string().optional() })).default([]) })`. The form's `defaultValues` are `initial ?? { id: '', name: '', price: 0, image: '', category: 'clothing', group: 'clothing', section: 'men', description: '', images: [], sizes: [], variants: [] }`. The `useFieldArray` hooks are `const images = useFieldArray({ control, name: 'images' })`, `const sizes = useFieldArray({ control, name: 'sizes' })`, `const variants = useFieldArray({ control, name: 'variants' })`.

The form layout uses shadcn `Tabs` (default value `basics`):
`<TabsList className="grid grid-cols-4 max-w-[520px]"><TabsTrigger value="basics">Basics</TabsTrigger><TabsTrigger value="images">Images</TabsTrigger><TabsTrigger value="sizes">Sizes</TabsTrigger><TabsTrigger value="variants">Variants</TabsTrigger></TabsList>` and four `<TabsContent value="...">` blocks:

1. **Basics** (`<TabsContent value="basics" className="mt-6 space-y-6">`): the seven core fields. Each field is a `<div className="space-y-1.5">` with a `<Label className="text-[13px] font-medium">Field label</Label>`, the shadcn `Input` (16px via the Plan 01-03 override) registered via `{...register('fieldName')}`, a `<p className="text-[13px] text-[#8B2E1F]">{errors.fieldName?.message}</p>` if there's an error, and for the enum fields (`category`, `group`, `section`) a shadcn `Select` with the three options each. The `id` field helper text is `<p className="text-[13px] text-[rgba(26,24,20,0.6)]">Lowercase, digits, and dashes. Used in the URL.</p>`.

2. **Images** (`<TabsContent value="images" className="mt-6 space-y-6">`): the primary `image` field as a labeled text input at the top (the form accepts either a typed path or a path returned by the dropzone), then the `<ImageDropzone onUploaded={(path) => images.append(path)} />` (the dropzone from the previous task), then a list of the current `images` rows. Each row is a card with the image URL, a preview `<img src={url} className="w-16 h-16 object-cover rounded" />`, a one-line truncated read-only `<Input value={url} readOnly />`, and a small `<Button type="button" variant="ghost" size="icon" onClick={() => images.remove(index)}><X className="h-4 w-4" /></Button>`. Below the list, a small `<button type="button" onClick={() => images.append('')} className="text-[#B8763A] text-[14px] font-medium">+ Add another image</button>`.

3. **Sizes** (`<TabsContent value="sizes" className="mt-6 space-y-4">`): a list of `sizes` rows where each row is a flex row with an `<Input {...register(`sizes.${index}`)} placeholder="e.g. M" />`, and a remove `<Button variant="ghost" size="icon" onClick={() => sizes.remove(index)}><X className="h-4 w-4" /></Button>`. Below the list, `<button type="button" onClick={() => sizes.append('')} className="text-[#B8763A] text-[14px] font-medium">+ Add a size</button>`.

4. **Variants** (`<TabsContent value="variants" className="mt-6 space-y-4">`): a list of `variants` rows where each row is a card with three fields: `colorName` (text input), `colorValue` (text input with placeholder `e.g. oklch(0.42 0.08 130)` and helper `Use an oklch(...) string. The store will tint the photo.`), and `image` (a small input that can be either a path or the result of an inline upload — for v1, the variant `image` is text-only; the dropzone on the Images tab handles the gallery). Below the list, `<button type="button" onClick={() => variants.append({ colorName: '', colorValue: '', image: '' })} className="text-[#B8763A] text-[14px] font-medium">+ Add a variant</button>`.

Below the `Tabs`, a sticky footer with the Save button:
`<div className="sticky bottom-0 -mx-8 px-8 py-4 bg-[#FAF7F2] border-t border-[rgba(26,24,20,0.08)] mt-8"><Button type="submit" disabled={isSubmitting} className="w-full md:w-[200px] md:ml-auto md:block bg-[#1A1814] text-[#FAF7F2] hover:bg-[#1A1814]/90 h-12 rounded-lg font-medium">{isSubmitting ? 'Saving…' : 'Save product'}</Button></div>`.

The `onSubmit` handler:
`const onSubmit = async (values: ProductFormValues) => { const url = initial ? `/api/admin/products/${encodeURIComponent(initial.id)}` : '/api/admin/products'; const method = initial ? 'PUT' : 'POST'; const res = await fetch(url, { method, headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(values) }); if (res.ok) { toast.success(initial ? 'Product updated.' : 'Product saved.'); router.push('/admin/products'); } else { const data = await res.json().catch(() => ({})); toast.error(`Couldn\'t save. ${data?.error ?? 'Check the fields and try again.'}`); } };`.

The form is wrapped in `<form onSubmit={handleSubmit(onSubmit)}>`. The
page title is rendered above the tabs: `<h1 className="text-[24px] font-semibold text-[#1A1814] mb-6">{initial ? `Edit · ${initial.name}` : 'New product'}</h1>`.

Then create the two server-component pages that wrap the form:

- `app/admin/(authenticated)/products/new/page.tsx`:
`import ProductForm from '@/components/admin/product-form'; export default function NewProductPage() { return <ProductForm mode="create" />; }` (no initial).

- `app/admin/(authenticated)/products/[id]/page.tsx`:
`import { notFound } from 'next/navigation'; import { backendFetch } from '@/lib/backend'; import ProductForm from '@/components/admin/product-form'; interface PageProps { params: Promise<{ id: string }>; } export default async function EditProductPage({ params }: PageProps) { const { id } = await params; let data; try { data = await backendFetch(`/shop/products/${encodeURIComponent(id)}`); } catch { notFound(); } const initial = data?.product; if (!initial) notFound(); return <ProductForm mode="edit" initial={initial} />; }`.

<threat_model>
<surface>The form is a write path to the catalog. The form's zod schema
is the client-side guard, the backend `validateProductPayload` in
`backend/src/routers/clothes.ts:39-49` is the server-side guard. The
form POSTs to `/api/admin/products` (create) or PUTs to
`/api/admin/products/[id]` (edit) — both are auth-gated in Plan 01-04.
The image dropzone posts to `/api/admin/upload` which is also
auth-gated and validates MIME and size.
</surface>
<risks>
- [T-Tampering] A client bypassing the zod schema can submit a
  malformed body. Mitigated by the backend's
  `validateProductPayload` re-validation, which checks all required
  fields, the section/group/category enums, and the price range.
- [E-Elevation of Privilege] Mass-assignment on `role` is not possible
  here (the form does not touch the `User` model; the product
  `productPayload` at `backend/src/routers/clothes.ts:23-37` is a
  whitelist that does not include `role`).
- [T-Tampering] XSS via a malicious product name. Mitigated by React's
  default escaping in JSX (no `dangerouslySetInnerHTML` anywhere in
  the form).
- [T-Tampering] Path traversal in the primary `image` text input.
  Mitigated by the backend's `productPayload` which trims and stores
  the string verbatim; the storefront serves it via `<img src={...}>`,
  which the browser resolves relative to the site origin. A path
  outside `/images/` is a static asset miss (404), not a server-side
  read of a sensitive file. The dropzone-bound uploads (D-18) are
  isolated to `/public/images/products/` and named by the server.
- [D-Denial of Service] A user spamming Save. Mitigated at the form
  layer by `disabled={isSubmitting}` and at the server layer by the
  existing auth gate.
</risks>
</threat_model>
