<objective>
Fix the uncommitted scroll-spy WIP in components/SideBar.tsx so the clicked sidebar card stays expanded for as long as its section is on screen. EXTEND the WIP (activeIndex, hoveredIndex, handleCardClick, observer); do not revert it.

Purpose: The WIP's observer only treats a section as active while it crosses a 20%-tall band at the viewport's vertical center (rootMargin shrinking top and bottom by 40%). The only real section, men-collection on /men, is a ~200px ClothingCard pinned just below the fixed navbar; it can never reach that band, so the observer's first callback after landing on /men takes the "nothing intersecting" branch and clears activeIndex, collapsing the card while the user is still on the section. Two more defects compound it: the callback judges visibility from a single entry batch (IntersectionObserver only reports CHANGED entries, so a still-visible-but-unchanged section is invisible to the batch), and activeIndex is never reset on route change so a stale card can stay expanded on pages with no sections.

Output: components/SideBar.tsx where "section visible below the navbar" == "card expanded", with visibility tracked across batches and state reset per route.

Known limitation (out of scope, do NOT build in this plan): women-collection and kids-collection element ids exist nowhere in the codebase yet, so Women/Kids clicks set the active state without scrolling. This fix makes the spy correct for sections that exist; adding those sections is separate feature work.
</objective>

    Edit components/SideBar.tsx in place, keeping all existing WIP behavior that already works (items config, handleCardClick, hover handlers, isExpanded -> 'active' class, styled-components CSS). Four targeted changes:

    1. Hoist the items array to module scope (above the component). It is static config; today it is recreated per render and captured by the useEffect without being a dependency, which is fragile and a lint hazard. Keep the exact same three entries and fields.

    2. Replace the observer options: change rootMargin from the middle-band shrink to '-136px 0px 0px 0px' (136px = the 8.5rem fixed-header offset, so "visible" means any part of the section showing below the navbar). Keep the threshold array [0, 0.25, 0.5, 0.75, 1] for ratio granularity. This is the core fix: a section now counts as active whenever any pixel of it is on screen below the navbar, so the 200px men-collection at the top of /men (and any future bottom-of-page section) stays active the whole time it is visible.

    3. Rewrite the callback to track visibility ACROSS batches: keep a Map of section id to intersectionRatio in an effect-local variable; on every callback, for each entry set the ratio when entry.isIntersecting and delete the id when it is not; then compute the active id as the map entry with the highest ratio and call setActiveIndex with its items index, or setActiveIndex(null) only when the map is empty. This fixes the batch-semantics bug where a still-visible section absent from the current batch caused a wrongful clear, and it scopes the clear-branch to "genuinely nothing visible" (the spec's "no section is active" case).

    4. At the top of the same useEffect (which re-runs on pathname change), call setActiveIndex(null) before observing, so a card active on /men never stays stale-expanded after navigating to a page with no observed sections.

    Do not touch handleCardClick's click-set activeIndex: the click still expands immediately, and the corrected observer then maintains it while the section is visible, takes over when a different section becomes more visible, and clears only when nothing is visible. Do not modify the CSS block or any other file. Do not add ids or sections to pages.
