# Plan 01-01: Substrate — env, deps, boot handling

<goal>
Create the env-var contract the auth foundation depends on, install the new
backend and frontend dependencies, and add the boot-time env validation so the
backend fails fast when `JWT_SECRET` is missing and warns when the default
`MONGODB_URI` is used in production. This is the Wave 0 substrate — no auth
or UI logic, just the foundation that every other plan builds on.

</goal>

<context>
Per `01-CONTEXT.md` D-04 (signed JWT in `clothly_session` cookie, `JWT_SECRET`
required at boot, server fails fast) and D-24 (`MONGODB_URI` env-driven with
dev default + production warning). Per D-13, all new storefront fetches use
`cache: 'no-store'` (already the pattern in `lib/backend.ts:7-22`).

The backend currently has only `express`, `mongoose`, `nodemon`, `typescript`
in `backend/package.json:16-21`. The new auth surface needs `jsonwebtoken`
and `bcrypt` (and `@types/*`). The Edge-runtime middleware needs `jose` at the
root. None of these are installed yet.

The root `tsconfig.json:25-32` includes `**/*.ts` with no `backend` exclude,
which causes the root `tsc` to try to typecheck the backend against the
frontend's ES2017 + bundler-module-resolution config (Pitfall 10 in
`01-RESEARCH.md`).

The existing `backend/src/index.ts:6-7` reads `PORT` and `MONGODB_URI` from
env with a localhost default. It does NOT validate `JWT_SECRET` and does NOT
warn when the default URI is used in production.

This plan delivers the substrate. Plan 01-02 mounts the auth router that
consumes `JWT_SECRET`. Plan 01-03 mounts the middleware that also uses it.

</context>

<threat_model>
<skip_if>low-risk utility work, no auth surface, no external input</skip_if>
<surface>Boot-time environment validation only. No new HTTP endpoints, no new
user inputs, no DB writes. The plan only validates that the server refuses
to start with a missing secret and warns on default-DB-in-prod.
</surface>
<risks>
- [S-Spoofing] A missing `JWT_SECRET` would silently break every signed-token
  verify in the system. Mitigated by the boot-time fail-fast: the server
  refuses to start, surfacing the problem before any request can reach it.
- [I-Information Disclosure] The default `MONGODB_URI` in production would
  silently point at a developer-local instance, leaking any data the
  developer loads there. Mitigated by the prod-warning log; the operator
  must see the warning and override the env var before traffic is allowed.
</risks>
</threat_model>
